# 文献级索引卡（`audit/leads/papers/`）

一篇文献往往同时覆盖**几十个**库内源（样本汇编、统计文章、望远镜观测汇总）。给每个源都写一张
源级线索卡会把 `audit/leads/` 变成 GCN 的复印件，并在并行审核时互相撞车。

文献级索引卡解决的就是这件事：**一篇多源文献只有一张卡**，承载「它涉及哪些源、各自在哪张表、
谁已经留了源级卡」，把 N 张卡的索引压成 1 张可检索的表。契约的判据和工具见下。

## 两种卡的分工（别混淆）

| | 源级卡 `audit/leads/<源ID>.md` | 文献级卡 `audit/leads/papers/<paper_key>.md` |
|---|---|---|
| 承载 | 该源在文中的**可执行线索**：原文口径、原始行、待核对项 | **索引**：本文涉及哪些库内源、表号、谁留了卡 |
| 何时写 | 过「增量门槛」（见下）才写 | 本文覆盖 **≥3 个**库内源时写 |
| 参与状态机 | 否（只是交接信息） | 否（纯索引） |
| 谁读 | 接手审核该源的人 | 想找「还有哪些源被这篇文提到」的人 |

**文献级卡不代替源级卡**：它只说明「这里可能有事」，不含可采纳的数值。接手者仍要自己开原文。

## 文件名与元数据

文件名 = `paper_key`：小写字母/数字，一作姓氏 + 年份最省事，例如 `ershhova2020.md`、
`minaew2020.md`、`guidorzi2025.md`。**不要**用 DOI（斜杠会让文件名失效）。

第一个 `##` 标题之前是元数据区（工具只解析这里，格式 `- key: value`）：

| 键 | 必填 | 含义 |
|---|---|---|
| `paper_key` | ✅ | 必须与文件名一致 |
| `paper` | ✅ | 文献出处（作者+年+刊物+DOI；VoR 是否可得写进正文） |
| `date` | ✅ | 建卡日期 `YYYY-MM-DD` |
| `helper` | 建议 | 建卡人 `人名@代理` |
| `sources` | ✅ | 本文涉及的**库内已存在**源 ID，逗号分隔；工具靠它反查「某源被哪篇多源文献提到」 |
| `out_of_repo` | 可选 | 本文涉及但**库内没有**的源；每个都必须已开 `new-source` Issue |

`sources` 里出现 `info/` 不存在的 ID → `validate.py` 警告：库外新源一律走 Issue，不写进卡。

## 正文建议结构

1. `## 为什么是文献级卡`：本文的规模（覆盖多少源、哪些是汇总表、哪些是专篇表）。
2. `## 涉及源一览`：表格 `| 源 | 表号 | 源级卡 | status | 增量判读 |`。
3. `## 增量门槛判读`：哪些源过门槛（该有源级卡）、哪些不过（只有汇总表转引，不开卡）。
4. `## 待决`：需要维护者裁定的事（例如「汇总表规模过大，是否整表不入库」）。

## 增量门槛：源级卡只在**有增量**时开

审自己那一源时，若该文献还覆盖别的库内源，**满足以下任一条**才为那个源写源级卡：

1. 文献给出了库内 GCN / 目录检索**拿不到**的数值（未单独发 GCN 的测光表、作者自算的 ΔT / m_OT / 定标）；
2. 对同一次测量给出了**不同口径**（换成库内口径时会真出错的地方：T0 锚点、滤光片、星等系统）；
3. 为库内源提供了**新的正式文献引用**（bibcode 级，供 `articles[]` 与可追溯性用）。

**明确不开卡的情形**（写进文献级卡即可）：

- 纯「汇总表转引 GCN」的行（例如 Ershova+2020 表 20 那类逐暴日志：数值与 GCN 同源、可直接检索到）；
- 只是文末致谢/样本列表里出现源名，没有任何该源的量；
- 图上读数、且原文没给数表。

> 判据的精神：卡是**为接手者省事**，不是为文献做目录。一张卡如果只写着「该文有一行，请自己去看」，
> 它带来的检索负担大于收益——那行信息应当压进文献级卡的一行表格里。

## 硬性禁令（与源级卡一致）

- 不得修改任何目标源的 `info/` `lc/`，不得为其写 `extra_data.audit`，不得在其 `comment` 留话。
- **不得把源 ID 写进 PR 标题**（`gh pr list --search "in:title <源ID>"` 会误判成认领）。
- 不得在卡里做单位换算、T0 换算、消光改正、去重判断——那是接手者的审核动作。
- 文献级卡不承载任何源的 `free/claimed/reviewed` 状态。

## 工具

```bash
python3 tools/validate.py                        # 卡格式/命名/登记源存在性/同 DOI 重复（警告级）
python3 tools/audit_queue.py --leads             # 全部源级卡 + 文献级卡摘要
python3 tools/audit_queue.py --paper ershhova2020  # 展开一张文献级卡（含各源当前状态）
python3 tools/audit_queue.py --check-leads --base origin/main  # PR 守卫：新增卡规模/形态（警告级）
```

PR 守卫的判据（都只警告、不阻断）：

- 一个 PR 新增 **≥5 张源级卡**却没有任何文献级卡 → 提示先用文献级卡收敛；
- 新增源级卡里 **≥3 张**自述为「转引/汇总表」性质 → 提示按增量门槛这些不该开卡。

## 历史欠账不追溯

2026-10-24 之前合并的源级卡不回滚（与 Issue #69 的伪形 alias 口径一致）。文献级卡里用
「增量判读」列标明每张历史卡属于「过门槛」还是「转引型」，后者在该源被真正审核时
**顺手删掉源级卡、读文献级卡**即可。
